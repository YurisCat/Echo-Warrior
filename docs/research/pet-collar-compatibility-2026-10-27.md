## 实施边界

持久身份仍由本体绑定及遗物决定，不固定实体 UUID，不恢复完整第三方实体快照。
项圈存储须采用独立可选字段，旧存档缺少字段等价于未佩戴；不改变既有绑定格式的解释。
暂时缺少第三方模组时不主动抹除其已保存数据；此规则不等于支持任意模组卸载或游戏降级。
两个模组的数据分别保存，禁止因字段名称相似而把一个模组的附魔交给另一个。

恢复顺序必须先恢复属性，再结算当前生命值。属性不能重复叠加。
死亡、遗物转装、第三方换装和旧代实体不得写回错误遗物。
冷却、消耗性充能和临时效果需要分别审计，不能把完整实体数据当作项圈内容复制。

## 实际实现

- 新字段 `EchoWarriorPetCollars` 放在遗物自定义数据中，按模组 ID 分开，Schema=1。
  即时第三方换装写回与本体离场/跟随迁移保存共同守卫；恢复先走原模组属性刷新，再设置生命。
- 当前 UUID、召唤器和 generation 三重校验；服务端拒绝英灵的客户端原始附加 NBT 覆盖。
  普通宠物仍进入原处理器，线程调度不从网络线程读取世界。
- 未识别的未来 Schema 拒绝创建，不扣燃料、不清掉历史数据。临时缺少依赖保留字段，
  不把该规则表述成整个第三方模组可以随意卸载的承诺。
- 换项圈仍由原物品逻辑返还一件旧项圈；主动离场、死亡不产生额外项圈掉落。
- 宠物床、所有权契约、新捕网封存被阻止；旧已填充网不直接还原英灵，网弹只返还一件原网。
  新的英灵复活/灯笼请求在加入队列前阻止，旧请求只在读取时过滤，普通宠物请求保留。
- 罗盘条目以召唤器与当前遗物派生稳定 ID；实体 UUID 不作为持续控制权。
  实际召回调用本体事务，检查燃料、数量与当前控制者；旧位置不允许强载旧代实体。
- 26.1.2 英灵为 PathfinderMob，显式桥接宠物识别及控制者；不改变实体继承树。
  该版本额外限制年龄诅咒的 AgeableMob 强转，仍保存附魔本身。
- 完整处置表见 [附魔清单](pet-collar-enchantments-2026-10-27.md)。
  Pet Home 固定包分别有 44 / 40 / 40 项，驯养革新有 35 项。
  “交给原模组效果”不等于每个战斗触发、声音和渲染层均已人工验收。
- 已审计第三方命令：固定源码中 Pet Home 的 `pet_home_config` 仅打开客户端配置界面，
  没有发现独立的英灵生成命令；原版管理员命令和其他未列出的模组不属于兼容入口承诺。

## 已定位问题与处理

1. 第三方把项圈保存在实体附加数据，而英灵收回重召创建新实体：改为权威遗物承载。
2. 某些固定包的 CollarTickTracker 在 keySet 遍历时删除 HashMap：只对检测到旧字节码的分支复制键集合，
   不覆盖已使用迭代器删除的分支；真实双计时器同刻到期测试覆盖。
3. 1.20.1 Fabric 的网络类客户端方法体会在专服验证时解析 LocalPlayer：专服仅移除该客户端方法体，
   客户端与服务端网络处理保留；正式客户端仍需独立启动验收。
4. 26.1.2 Fabric Pet Home 1.1.3 把两个客户端访问器列在公共 Mixin 配置：精确验证目标后专服移出两项，
   保留另外 37 项公共 Mixin。没有修改依赖 JAR、整体关闭配置或吞掉注入错误。
5. 1.20.1 Forge 要求 `#c:ores`，该加载器实际提供 `#forge:ores`：增加可选、非覆盖式别名，
   真实铁矿石 tag 断言覆盖。新版本按其真实常规 tag 检查。
6. respawn 请求在新版由普通类改成 record：分别读取 `getEntityTypeLoc()` / `entityType()`；
   新旧请求及普通宠物的实际列表读写测试覆盖，不能只测空队列。
7. Forge 与 Fabric 的相同包名不表示同一 handler 布局：固定 Forge 包使用内部 `$Handler`，
   以字节码选择专用 Mixin；原包真实 handler 调用验证拒绝与透传。

测试夹具问题单独归类：Fabric 真实交互需要先走 UseEntityCallback；模拟玩家不能在实体跟踪器仍持有时
把连接重置为 null；处理器嵌套排队须等待队列屏障；NeoForge 延迟注册句柄需先解包；
1.20.1 使用 DIWorldData，现代版本使用 PHWorldData。均保留原失败证据。
主线 Windows 测试实例显式使用 NIO，避免不适用的 kqueue/epoll 探测触发日志库异常；没有忽略该错误。
新世界地形夹具只在第一次启动执行，第二次保持同一世界验证项圈磁盘恢复和同步自测。
