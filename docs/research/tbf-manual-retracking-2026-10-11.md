# TBF 取消追踪后的普通手动登记修复

日期：2026-10-11（Asia/Shanghai）。基于已发行 `0.2.6`，候选 `0.2.7-dev.1`；作者授权修复、在 FOXY-NODE 测试并在可发布时报告，本轮不上传平台、不推发布标签。

## 原因与实现

0.2.6 的 `TbfOwnershipMixin*` 对英灵的 `getCompatOwnerUUID` 返回空，目的是防止第三方把实际实体 UUID 登记为第二条宠物身份。取消追踪只将稳定条目标记为 muted，不删除本体归属。TBF 的羽毛事件与普通 `/tbf load` 共用 `ModCommands.loadPet`，仍经通用主人解析，因此返回 `NOT_A_PET`；只有已有 `tryForceLoadPet` 兼容入口解除 muted。已核对 Forge 正式 JAR 字节码与两条源码，旧自动测试仅验证 master 恢复，遗漏普通入口。

修复在两条可选兼容线新增 `TbfManualTrackingMixin*`，按映射后的精确 `@Desc` 注入共用手动入口。英灵复用已有权威校验：当前控制者、活动绑定、实体 UUID、代次匹配后恢复原稳定条目；TBF 原反馈方法继续显示既有翻译。羽毛事件外围的物品不足/成功后消费和命令注册的 OP 要求不变；普通宠物直接透传。自动主人解析保护不解除，本体实体、绑定、存档、燃料和召唤事务代码不变。

新入口及反馈方法加入 API 字节码门禁；新 Mixin 类和注册加入两线 JAR 基线。复用规则补充 PORT-033，当前设计和回声档案馆同步。只复用第三方已有文案，无本模组新增语言键。
