# Minecraft 1.20.1 兼容可行性评估

评估日期：2026-09-19。代码基准：`c9b521c`，Echo Warrior `0.2.1`。

状态更新：作者已于 2026-09-19 接受 Fabric + Forge 并授权实施。本文保留开工前评估与阶段计划；当前构建/测试进度以 `versions/1.20.1/README.md` 和 `PROJECT.md` 4.3 为准，不代表已经有完整可玩的 1.20.1 包。

## 1. 结论与范围

可行，值得进入最小工程验证；目前没有发现核心依赖缺失这一类明确阻断。工程工作量评估为中高：玩法和资产复用基础较好，但要跨过物品数据、网络和 Forge 发行映射三个重要边界，不能只下调版本号。

- 目标建议固定为 **Minecraft 1.20.1，Fabric + Forge**，不一次覆盖整个 1.20.x 系列。
- NeoForge 的 1.20.1 版本确实存在，但其官方用户指南明确建议在该游戏版本使用 Forge。这里的选择不是说 NeoForge 做不到，而是遵循该版本的支持路线，避免额外维护一个不推荐的目标。[NeoForge 官方说明](https://docs.neoforged.net/user/docs/)
- 26.1.2 与 1.21.1 继续保持 Fabric + NeoForge，不替换现有四包。新兼容线完成后，发布矩阵才由四包扩为六包；暂不增加第七个 1.20.1 NeoForge 包。
- 最终建议范围仍是五名英灵及当前完整功能：召唤器、遗物/天赋/传承、饰品、考古与罗盘、知识与教程、回收箱、配方和已有多语言。罗马军团兵是验证顺序，不是最终缩水为一个英雄。
- 默认只做功能移植，不承诺 26.1.2/1.21.1 世界可以直接降级到 1.20.1，也不引入新英雄、新机制或声音扩充。

仓库当前 Wrapper 为 Gradle 9.5.1、1.21.1 使用 ModDevGradle 2.0.141；与旧游戏目标的完整组合尚未试编。先用仓库 Wrapper 验证，不修改系统 `JAVA_HOME`，不为旧版全局降级 26.1.2 的 Java 25 工具链。如果必须使用独立 Wrapper/插件组合，记录复现失败后再单独对齐，不能静默改变现有构建路线。GeckoLib 官方说明 1.20.4 及以下没有 common 制品，共享模块的编译依赖必须选用正确的加载器制品并处理映射。[GeckoLib 4 安装说明](https://github.com/bernie-g/geckolib/wiki/Installation-%28Geckolib4%29)

## 3. 主要改动面

代码盘点：当前 1.21.1 有 138 个 Java 文件；其中 10 个文件直接涉及 `DataComponents`、`CustomData` 或 `ItemContainerContents`，两类自定义网络 payload 使用现代编解码接口。此统计只帮助定位入口，不等于修改量或复用百分比。

| 改动面 | 风险 | 本项目需要处理什么 |
| --- | --- | --- |
| 物品数据与保存 | 高 | 将组件式物品存储适配为旧版 `ItemStack` NBT；保留 UUID、八槽内容、技能/箭型、燃料、经验/天赋、书签、修订号及空槽语义 |
| 网络、菜单、创造栏 | 高 | 分别适配 Fabric 旧网络接口与 Forge 通道；重新验证真实槽号、鼠标栈、客户端预测和服务端提交，不能只换包类名称 |
| Forge 构建、映射、Mixin | 高 | 为旧 Forge 建适配层，核对注册/事件生命周期、依赖映射、访问变换和注入签名；真实发行包必须经过启动验证 |
| AI 与动画 | 中高 | SBL 版本变化、实体/属性 API、GeckoLib 4 小版本差异；重点提前复验弓箭手完整射击、收箭、转火和攻速变化 |
| 资源、配方与世界数据 | 中 | 将目录和 JSON 内容都转换到 1.20.1 格式，审计目标声音/物品 ID、标签、考古池及战场生成接口 |
| GUI 与渲染 | 中 | 旧版绘制 API、透明层、物品渲染、坐标、斜光、工具提示和第一人称状态更新，不能只以编译通过验收 |
| 本地化 | 文字复用高，布局仍需检查 | 复用现有 14 个 locale 文件（包含地区别名），同步 622 个键；新增第三条语言目录及 UI 守卫，不重新翻译同一套文案 |

### 3.1 物品数据是首要风险，不是所有 NBT 都要重写

1.20.5 才引入当前物品组件体系，并调整网络及注册表序列化；因此 1.21.1 → 1.20.1 恰好跨过这个边界。[Fabric 官方迁移说明](https://fabricmc.net/2024/04/19/1205.html)

现有 `CustomData` 内已经有 NBT，可以复用字段含义；不能直接复用的是组件外壳、容器内容、复制/比较、物品栈序列化以及同步接口。优先建立集中读写入口，不让英雄类和 GUI 各自拼写 NBT。世界 SavedData 继续是绑定权威，物品只是镜像；不能因改用 NBT 退回客户端物品说了算。

首批适配入口：`EchoSummonerItem1211`、`SummonerStackContents1211`、`SummonerFuel1211`、`EchoRelicState1211`、`EchoRelicProgress1211`、`EchoCompassItem1211`、两种书的 StackData、`SummonerMenu1211` 和对应自测。特别检查嵌套容器/收纳袋里的召唤器，旧版结构不能继续按现代容器组件遍历。

网络保持“服务端校验请求、主线程提交状态、客户端接收结果”。Forge 1.20.1 可采用 `SimpleChannel`，必须核对双方字段顺序、大小限制、玩家权限、槽位和 UUID，而非信任客户端上传的完整绑定。[Forge SimpleImpl 文档](https://docs.minecraftforge.net/en/1.20.1/networking/simpleimpl/)

### 3.2 资源目录和格式必须一起转换

1.21 将多种数据包目录改为单数。下移要恢复目标版本的 `recipes`、`loot_tables`、`tags/items` 等路径，也要检查配方结果、战利品 NBT/组件函数与加载条件的旧格式；单纯重命名目录仍可能不加载。[Fabric 1.21 迁移说明](https://fabricmc.net/2024/05/31/121.html)

1.21.1 已完成的 GeckoLib 4 资产、旧物品模型覆盖、透明草侧面、状态图标和多语言布局具有复用价值，但必须用最终 JAR 审计和游戏加载确认。现有声音替代/缺失仍需列版本差异；不因继续下移而宣称旧版拥有全部新版原版声音，也不将提取新版原版音频塞入模组作为默认方案。

## 4. 1.21.1 踩坑审计与回归入口

已核对 `PROJECT.md` 的候选历史、最终代码与 `scripts/check-1.21.1-baseline.ps1`。原手册已有 17 条经验，核心内容并未丢失；本轮扩充动画及 GUI 规则，补入两条原本只散见于修复历史的独立根因。

| 既有问题 | 手册条目 | 已有自动防线 / 仍需观察 |
| --- | --- | --- |
| 缺物品、配方、创造页、技能/天赋说明或出现翻译键 | PORT-001、002、017 | 注册/JAR/键与调用点审计；实际取得入口及悬浮状态仍抽查 |
| 创造投入吞物、饰品取出又出现、销毁召唤器不销毁英灵 | PORT-005、006、012 | 真实创造点击集成测试、服务端修订与绑定自测；新加载器逐项覆盖正反例 |
| 弓箭手反复拉弓、放箭抽搐与突然转头 | PORT-003（扩充） | 持有完整动画序列、触发速度/时长及父骨骼逆变换守卫；连续动作观感人工确认 |
| 斜光不可见/错位、提示被图标挡住 | PORT-008（扩充） | 队列、批次刷新、绘制层、槽位锚点和延迟提示断言；实际像素与 GUI 缩放人工确认 |
| 回收箱紫黑/缺卡扣、Shift 物品图标不切换、罗盘颜色/消息不对 | PORT-009、010、014 | 渲染生命周期、朝向、谓词与消息路径守卫；物品展示和最终反馈人工确认 |
| 翻页或装入燃料/饰品反复触发手臂动作 | PORT-015 | 稳定物理身份与主副手快照自测；两种书和召唤器都要复测 |
| 长翻译越界、标题压图标、地区语言回退 | PORT-016、017及本地化配置 | 全键/地区别名/UI 路径检查；长拉丁文、俄语、CJK 各抽查 |
| 可疑草未染色或整面全绿 | PORT-018（新增） | 现有双加载器渲染层、透明 overlay、颜色提供器和 JAR 守卫；群系并排观察 |
| 禁拾取箭矢正常射击但退出保存报错 | PORT-019（新增） | 已有非空箭栈守卫，本轮追加禁拾取策略断言；旧版需补实际箭实体保存/重载测试 |

源码字符串守卫能防已知实现被删掉，不能证明整个系统正确。新线必须把这些规则转换成目标 API 下的等价断言，并优先补实际存取、点击和服务端状态测试，而不是照抄 `1211` 类名后让检查“变绿”。

## 5. 推荐实施顺序与退出条件

### 阶段 0：冻结可运行的构建组合

- 在作者确认 Fabric + Forge 后，建立独立工程，明确 Java 17 游戏/字节码工具链与构建 JVM。
- 接通两个加载器、SBL、GeckoLib、最小注册、客户端入口、Mixin 与专服安全。
- 构建两个真正的发行 JAR；分别装入隔离客户端和专服，验证依赖、重映射和 Mixin，而不只运行开发启动任务。
- 退出条件：两个加载器的发行 JAR 可启动、专服正常关服，依赖版本及可复现命令记录完毕。若失败，先报告具体依赖/插件阻碍，不把大批玩法代码搬入未验证底座。

### 阶段 1：先验证状态与容器

- 完成 NBT 适配、世界绑定、UUID/代次、修订号、原子八槽提交和旧网络通道。
- 自动测试：空槽/满槽存取、保存往返、重登、旧菜单回写拒绝、重复 UUID、嵌套容器发现、跨维度与旧投射物失效。
- 创造模式必须区分投入、拿出、快速删除、X、点回目录、关闭界面和快捷栏预设覆盖；普通搬运、装箱与丢地不得误删。
- 退出条件：两个加载器服务端最终物品数与绑定一致，不吞物、不复制、不恢复旧状态。

### 阶段 2：一名完整英雄 + 提前验证弓箭手

- 罗马军团兵完整闭环：取得遗物 → 装入 → 召唤 → 跟随/战斗/技能 → 保存恢复 → 遣散/销毁。
- 同时验证 GUI、首次实体渲染、主副手状态更新、投入反馈与提示层级。
- 紧接着验证埃及弓箭手的完整射击序列、不同攻速、转火、收箭和投射物保存；不把最有历史风险的动画留到全量迁移后才看。
- 退出条件：自动状态检查通过，作者只需按本阶段的短视觉清单确认表现，不要求每次补丁把所有内容从头玩一遍。

### 阶段 3：补齐全量内容及多语言

- 完成其余英雄、遗物/饰品/传承、考古生成、罗盘、知识、教程、回收箱及所有取得入口。
- 以稳定内容 ID 比较功能清单；31 个配方等数据资源按旧版格式转换，不能只比较文件数量。
- 把新语言目录及界面审计接入 `scripts/check-localization.py`，保留 `zh_hk = zh_tw` 和拉美地区别名策略，不仅迁移中英。
- 基准译文未变化时复用已完成的语言审校，但 1.20.1 字体与排版仍需短视觉抽查；不自动 `--mark-current`，也不继承 0.2.1 的发布豁免。

### 阶段 4：交付与发布接入

- 双加载器构建/JAR 审计、真实发行包客户端与专服测试、保存/网络与创造交互回归。
- 接入 `scripts/run-test-client.ps1` 的独立版本目标：自动进入测试世界后暂停释放鼠标；只关闭本轮启动的进程，不关闭作者其他模组的游戏，不自动启动并行客户端。
- 初次验证使用独立新测试世界；世界生成变化需要新世界/新区块时明确说明。绝不复制高版本玩家世界后尝试直接降级。
- 人工集中确认动画、音效、GUI/图标/光效和实际多人体验；逐次修复只重测受影响路径，最终汇总已测证据与残余风险。
- 成熟后才修改发布准备脚本、GitHub Actions 及 CF 元数据为六文件矩阵；Forge 包标注 Forge。运行现有本地化发布门禁，是否 Release/是否接受残余风险仍由作者当次决定。

## 6. 主线与 Stonecutter

日常功能继续优先 26.1.2 Fabric；完整节点稳定后同步旧版。1.20.1 的具体实现从距离较近的 **0.2.1 的 1.21.1 代码**出发，但玩法规则仍以 `PROJECT.md` 和主线为准，不能用更早内部候选作移植底稿。

新增第二条旧版线触发既定 Stonecutter 复评。当前建议仍先采用独立版本目录完成最小工程，不把全仓库重构当作前置条件：此次 NBT、网络与加载器差异较大，预处理工具不能消除这些 API 差异。先统一内容清单、语言校验和可共享资源生成；纵向切片完成后依据真实重复量，再决定是否用 Stonecutter 管理共用源码。这是阶段性建议，不是永久排除。
