# 外语本地化审阅流程

## 目标

作者只需要判断玩法含义、语气和文化边界是否正确，不需要具备日语、俄语、西班牙语或葡萄牙语能力。外语自然度不能通过作者“看起来像不像”来验收，而应由独立的翻译与审校步骤、自动检查和游戏内排版测试共同保证。

## 文风基准

- 每条文本先传达一个明确的玩法信息。优先写清楚对象、动作、数值、条件和结果。
- 使用目标语言中真实游戏会采用的普通表达，不为显得华丽而堆叠抽象词、宣传词或近义词。
- 技能和物品说明保持简短。一个句子能说清时不拆成对称的三句，也不在结尾补充没有机制信息的总结。
- 不机械照搬中英文语序。译文应像目标语言原生写成，同时保持原文的确定程度、神话/史实边界和作者语气。
- 避免模板化转折、空泛的意义拔高、连续破折号、自动生成式小标题以及“总结来说”一类收尾。
- 文化专名可以保留音译，但正文必须让玩家理解实际效果；不能用气氛描写替代机制说明。
- 英文及其他语言完成初稿后进行一次删减编辑：删除没有新增事实、机制、语气或必要文化信息的句子。

## 角色分离

每种语言至少经过两个彼此独立的模型角色：

1. **译者**：同时读取 `zh_cn`、`en_us`、术语表和文本所在界面，产出目标语言。
2. **审校者**：不读取译者的解释，只比较源文本、术语表和译文，检查语义遗漏、机械直译、术语漂移、语法、文化名词及 UI 长度。

同一次模型调用的“自我检查”不能替代独立审校。若译者和审校者意见冲突，由 Codex 汇总为中文问题，不让作者直接判断外语句子。

## 作者收到的审阅卡

需要作者决定的每一项必须按下列格式提供：

```text
键：gui.echo_warrior.example
使用位置：召唤器技能提示

中文原文：攻击有概率使目标流血。
英文原文：Attacks have a chance to make the target bleed.
目标语言：<译文原样>

中文直译回译：攻击时有一定概率让目标进入流血状态。
自然中文释义：每次攻击均可能施加流血。

术语对应：
- 攻击 → <目标语言术语>
- 流血 → <目标语言术语>（与状态效果名称一致）

审校结论：通过／建议修改／必须修改
风险：无／含文化专名／可能过长／语气偏差／数值或占位符风险
需要作者决定：只写中文问题；没有问题则写“无需作者决定”
```

作者只回答“中文回译是否符合设计原意”“推荐语气是否合适”“文化专名采用哪种解释”。目标语言的语法和自然度由审校者负责。

## 翻译批次

每批按语义区域处理，避免把 622 个键作为没有上下文的一整块文本：

1. 品牌、核心系统和固定术语；
2. 五名英灵、文明名与技能名；
3. 召唤器、模式、属性和反馈；
4. 物品、遗物、饰品、传承与天赋；
5. 教程手册与知识碎片；
6. 命令、死亡消息、标签和其他短文本。

术语批次先通过，再翻译普通句子。长篇教程与历史知识必须单独审校事实边界，不能因语言转换把“传说”“神话”“考古证据”改写成确定事实。

## 自动检查

每批译文合并前至少执行：

- JSON 可解析；
- 与双源语言键集合一致；
- `%s`、`%1$s` 等占位符完全一致；
- 主线与 1.21.1 兼容线文件一致；
- 香港繁中与拉美西语别名文件按当前策略逐字节同步；
- 检测空文本、残留翻译键、异常控制字符和大段未翻译文本；
- 对按钮、技能名、物品名和短提示设置长度预警；
- 对文化专名和 Minecraft 原版术语进行术语表匹配。
- 教程书等受限界面必须按实际宽高溢出缩放或换行，不得只为某个语言代码开启布局保护。

繁体中文还会检查已知的机械转换陷阱，例如把“推导出”转成“推汇出”、把一般图像和类型写成“影象”和“型别”，或继续使用“自定义”“揹包”等非目标用词。确定性的固定术语和错误片段应加入脚本门禁；只涉及语气或上下文取舍的项目仍由人工审校，不把整种语言简化成盲目的全局替换。

`scripts/check-localization.py` 负责发布级结构和过期检查；翻译生成阶段可以增加更严格的长度及术语检查，但不能降低发布门禁的规则。

## 游戏内验收

语言正确不代表界面可用。第一批语言至少覆盖下列代表性风险：

- `zh_tw`、`zh_hk`、`ja_jp`：CJK 字体、标点、书页分页和字形缺失；香港繁中目前沿用 `zh_tw`，尚非港式用语独立审校；
- `ru_ru`：西里尔字母及长按钮、长悬浮框；
- `pt_br`、`es_es`、`es_mx`：长拉丁文本、性数一致和换行；
- 所有语言：召唤器、技能提示、天赋、教程手册、知识碎片、创造栏和物品悬浮框。

完整视觉验收至少在一个 1.21.1 客户端和一个 26.1.2 客户端执行；其余加载器完成构建与启动冒烟检查。只改变翻译资源通常不需要新世界。

## 接受标准

只有同时满足以下条件，才能对某语言运行 `--mark-current`：

- 自动结构检查通过；
- 术语批次已经锁定；
- 独立审校没有未解决的“必须修改”；
- 作者已经处理所有中文语义问题；
- 代表性界面完成视觉验收，或明确记录为本次发布接受的剩余风险。

Alpha／Beta 可以由作者明确放行未完成语言；Release 默认应完成第一批目标语言。紧急崩溃修复若没有修改玩家可见文本，不会制造新的翻译工作。
