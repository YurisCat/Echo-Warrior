## 2. 审校者应读取的材料

1. `common/src/main/resources/assets/echo_warrior/lang/zh_cn.json`
2. `common/src/main/resources/assets/echo_warrior/lang/en_us.json`
3. 对应的目标语言文件
4. `docs/localization/TERMINOLOGY.md`
5. `docs/localization/TARGET_TERMS_CORE.md`
6. `docs/localization/REVIEW_WORKFLOW.md`

审校者不应读取译者的解释或推理，只根据双源语言、术语表、目标译文和文本所在界面作出判断。同一次模型对自己初稿的复核不能记作独立审校。

- 与英文完全相同的值已经抽查，均为人员姓名、机构名称、文化专名、技能借词或单独的标点后缀，不属于明显漏译。
- 繁中英雄名与制作人员姓名的内部不一致已经统一。
- 日语教程中的英雄名以及罗马技能重复文本已经与召唤器界面统一，避免同一概念出现两套译名。

## 4. 必须分批检查的内容

每种语言按以下六批给出独立结论，不要一次笼统判定整份文件：

1. 品牌、核心系统和固定术语；
2. 五名英灵、文明名与技能名；
3. 召唤器、模式、属性、状态和操作反馈；
4. 物品、遗物、饰品、传承与天赋；
5. 教程手册、知识碎片与历史叙述；
6. 命令、死亡消息、标签、制作名单和其他短文本。

重点确认以下问题：

- 目标语言是否把“英灵”稳定表达为历史战士的回声投影，而不是灵魂、鬼魂、亡灵或真实历史人物本人。
- 技能说明是否简短、直接并保留所有条件、数值、对象和结果。
- 历史知识是否保留“传说、可能、据称、考古证据”等确定程度，没有把争议叙述写成事实。
- Minecraft 原版术语是否符合对应官方语言，而不是逐字翻译中文。
- 同一英雄、技能、物品、状态和操作在教程、召唤器与物品提示中是否一致。
- 俄语、葡语和西语的长按钮、长物品名及性数／格变化是否自然。

## 5. 各语言高风险项

### 繁體中文

- 台湾 Minecraft 用语与标点习惯。
- 简繁机械转换残留，尤其是“推汇出、影象、型别、自定义、揹包”等已知错误。
- 英雄名、制作人员姓名和书名在不同界面的一致性。

### 日本語

- `エコー`、`エコー召喚器`、`伝承`、`送還` 是否自然且不会产生亡灵含义。
- 教程书名与五名战士名称是否符合游戏 UI 语感。
- 片假名、汉字和助词选择是否像日语原生游戏文本。

### Русский

- `Отголосок` 是否能稳定表示投影伙伴。
- 装置名、知识合集名、按钮和状态句是否过长。
- 数词、格变化、性数一致以及命令反馈的自然度。

### Português (Brasil)

- `Invocador de Ecos` 是否会被优先理解为人物；若会，提出不改变世界观含义的装置名方案。
- `Desmonte` 是否适合表示把物品拆解回收成材料。
- 巴西游戏文本中的语气、性数一致和动词祈使形式。

### Español (España)

- `Invocador de Ecos` 的人物／装置歧义。
- `desguace` 是否适合该回收箱的游戏功能。
- 西班牙用词、称谓和命令语气是否自然。

### Español (Latinoamérica)

- `Invocador de Ecos` 的人物／装置歧义。
- `desmantelamiento` 是否过长或过于工业化。
- 保持中性拉美表达，避免只适用于某一个国家的强地区词。

## 6. 审校输出格式

每一批先给出“通过／建议修改／必须修改”。只有存在问题的键需要展开审阅卡：

```text
键：
使用位置：

中文原文：
英文原文：
目标语言：

中文直译回译：
自然中文释义：

术语对应：
- 中文概念 → 目标语言术语

审校结论：通过／建议修改／必须修改
建议译文：
风险：无／文化专名／可能过长／语气偏差／数值或占位符风险
需要作者决定：仅写中文问题；没有则写“无需作者决定”
```

审校者还应在末尾给出该语言的总评：可进入视觉验收，或仍有必须修改项。作者只处理中文语义、语气和文化边界问题；目标语言语法与自然度由审校者负责。

## 7. 后续验收与接受基线

独立审校合并后重新运行：

```powershell
python scripts/check-localization.py
```

随后至少在一个 1.21.1 客户端和一个 26.1.2 客户端检查召唤器、技能提示、天赋、教程手册、知识碎片、创造栏和物品悬浮框。视觉验收前后都不应仅因文件存在而执行 `--mark-current`。

只有在结构检查、独立审校、作者语义裁决和代表性视觉验收全部完成后，才逐语言记录已接受基线。
