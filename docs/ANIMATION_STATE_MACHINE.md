# GeckoLib 战斗动画状态机与防抽搐规范

## 目的

本文档记录 Echo Warrior 英灵战斗动画的通用实现约定，重点解决以下问题：

- 动作结束时偶发闪回旧姿势、举起武器或四肢抽搐。
- 目标死亡、丢失或切换时，动画突然取消、重复起手或卡在末帧。
- 服务端伤害判定、投射物生成时机与美术关键帧不同步。
- 行走、待机、攻击、受伤和代码驱动头部系统同时修改骨骼时互相争夺。
- 攻击速度改变后，动作、开火帧和攻击间隔逐渐失配。

这些规则适用于所有使用 GeckoLib 的英灵，不属于埃及弓箭手的角色特例。角色专属的动画名称、骨骼名、关键帧和数值仍应保存在对应资产更新脚本、实体代码或角色说明中。

## 1. 必须区分的五条时间线

一个看似简单的攻击动作，运行时至少同时存在五条时间线：

1. **源动画时间线**：Blender／Blockbench／GeckoLib JSON 中动画真实长度及关键帧。
2. **服务端动作状态**：例如取箭、拉弓、瞄准、射击、近战、后撤步和收尾的开始与结束 tick。
3. **客户端同步状态**：实体数据从服务端到客户端后，客户端当前看到的动作编号、持续时间与目标。
4. **GeckoLib 控制器时间线**：当前触发动画、上一个缓存动画、混合时间、播放速度及停止状态。
5. **渲染帧时间线**：同一个游戏 tick 内可能渲染多帧，每帧的动画年龄和插值位置不同。

不能假设这五条时间线会在同一帧跨过动作边界。服务端在第 20 tick 结束动作，不代表客户端和 GeckoLib 一定会在第 20 tick 的第一个渲染帧同时结束。

### 核心不变量

每个战斗动作必须满足：

- 服务端始终拥有伤害、投射物、目标承诺和动作状态的最终决定权。
- 客户端在动作状态有效期间，始终存在一段能够提供合法姿势的动画。
- 动画控制器从当前动作退出前，不得短暂暴露上一段缓存动作。
- 下一状态的首帧必须能够从当前状态的末帧自然接续。
- 一个服务端攻击事件只能对应一次伤害或一次主投射物生成。
- 视觉动作可以等待或保持，但不得让服务器重复结算攻击。

## 2. 新动作必须先填写的定义

实现任何攻击或技能前，先确定以下信息：

| 字段 | 含义 |
|---|---|
| 动作状态 | 服务端使用的唯一状态编号和名称 |
| 源动画长度 | JSON 中的秒数及换算后的 tick 数 |
| 状态持续时间 | 服务端承诺该动作持续多少 tick |
| 事件帧 | 伤害、开火、位移、音效和粒子发生的源动画时间 |
| 循环语义 | Loop、Once 或 Hold |
| 控制器 | movement、action、pose 或其他专用控制器 |
| 骨骼所有权 | 全身、上半身、下半身、武器、箭矢、头部或表情 |
| 可否打断 | 哪些状态可以打断，以及打断前后如何收尾 |
| 目标承诺 | 起手、命中或开火后是否允许换目标 |
| 结束路径 | 返回待机、接下一击、收武器、后撤步或其他状态 |

如果这些字段还没有答案，不应直接在 AI tick 中零散地触发动画。

## 3. Loop、Once 与 Hold 的选择

### Loop

适用于待机、行走、持续瞄准和持续姿态。循环首尾必须连续，且循环动画不应自行承担一次性伤害事件。

### Once

适用于能够在动画时间线结束前或结束当帧安全退出的一次性动作，例如短促受伤反馈或具有明确接续动画的收尾。

注意：已经自然结束的 `PLAY_ONCE` 动画不一定适合再次调用 `stopTriggeredAnim`。某些情况下 GeckoLib 会重建已经完成的动画采样点，导致旧姿势在一个渲染帧内重新出现。

### Hold

适用于以下情况：

- 服务端承诺状态比源动画更长。
- 动画播放完后必须等待服务器确认、目标判定或技能阶段切换。
- 动作末帧本来就是安全等待姿势，例如拉满弓、举盾或攻击后的中立归位。

推荐使用 `thenPlayAndHold` 明确保持末帧，并在服务端状态真正结束时停止这个仍然活跃的保持动画。

Hold 不是万能方案。如果末帧不是安全姿势，长期保持会造成冻结；如果停止后没有合适的底层姿势，仍可能产生跳变。模型师和程序必须共同确认末帧用途。

## 4. 已确认的两类缓存姿势抽搐

### 4.1 远程攻击和目标死亡后的抽搐

埃及弓箭手曾在箭矢击杀目标或收弓结束后，手臂短暂跳回取箭、拉弓或射击姿势。

根因是：

- 投射物命中发生在服务端未来 tick，可能正好与下一轮取箭准备重叠。
- 射击、卸箭、收弓等 `PLAY_ONCE` 动画的自然结束，与服务端动作切换和客户端同步没有落在同一个渲染帧。
- 对已经完成的触发动画再次停止，或在边界直接落回空闲，可能让 GeckoLib 暴露上一段缓存的动画采样点。
- 取箭用的松散箭矢骨骼若恢复缩放或在模型原点短暂显示，会进一步放大闪动感。

通用处理原则：

- 把远程攻击拆成明确的取弹／搭箭、拉弓、瞄准、释放和收尾阶段。
- 开火前丢失目标可以进入取消或换目标路径；投射物释放后不得倒退回取箭阶段。
- 已承诺的释放动作冻结本次目标，除非更高优先级的近战自卫明确接管。
- 目标丢失使用短粘滞窗口，避免一个无目标 tick 立即触发完整收弓又马上重新举弓。
- 自然结束的收弓类 `PLAY_ONCE` 不重复停止；新动作直接替换旧触发器。
- 必要时在客户端对已确认的边界回放进行短窗口姿势保护，但不应以永久覆盖骨骼代替正确状态机。

### 4.2 近战动画早于服务端动作状态结束

埃及弓箭手的近战源动画长度为 `0.83333` 秒，约 `16.67 tick`；为了保证攻击完整且不被伤害动画打断，服务端近战状态持续 `20 tick`。

日志确认：动画约在第 17 tick 自然结束后，服务端仍保持近战状态约 3 tick。在这段空档中，动作控制器回退到了先前缓存的弓箭姿势，双臂和弓骨骼在一帧内进入拉弓状态，下一帧又恢复近战末帧；服务端直到第 20 tick 才真正结束近战。

当前通用修复方式：

- 近战使用 `thenPlayAndHold` 保持已经归位的安全末帧。
- 保持状态覆盖完整的服务端承诺窗口。
- 第 20 tick 正式结束动作时，再停止仍然活跃的近战 Hold。
- 不改变第 8 tick 的伤害判定、20 tick 的不可打断窗口和下一次攻击节奏。

这类问题不能只靠检查模型最后一帧发现。模型末帧可能完全正确，错误仍会发生在动画时间线已经不存在、服务端状态却尚未结束的空档中。

## 5. 推荐的战斗动作状态机

不要用“当前有目标就播放攻击、没有目标就停止”替代状态机。推荐将动作划分为以下阶段：

```text
IDLE / READY
    → PREPARE        取箭、举武器、蓄力
    → AIM / COMMIT   允许有限转火，但不重新起手
    → RELEASE        生成投射物或进入不可撤销挥击
    → RECOVER        保持或收回动作
    → EXIT           回到待机、移动、下一击或专用取消动画
```

### 目标丢失规则

- **PREPARE 前半段**：可以安全取消，使用与当前进度匹配的归位动作。
- **PREPARE 后半段／AIM**：优先短暂等待或切换到新的合法高威胁目标，不重新播放第一帧。
- **RELEASE 之后**：本次攻击已经承诺，目标死亡只影响下一轮选择，不回滚本轮动画。
- **RECOVER**：必须完成安全收尾，不能因为扫描到新目标而从第一帧重新举武器。
- **无目标粘滞期**：短暂保持最近合法姿势，确认没有替代目标后再收武器。

### 目标切换规则

- 同危险等级目标不能因为极小的距离变化每 tick 互相抢占。
- 更高危险目标可以接管尚未释放的攻击，但应保留当前动画进度。
- 释放或不可撤销挥击开始后，普通转火留给下一次攻击。
- 近身自卫可以拥有单独的最高优先级，但必须明确由哪个状态负责中断和收尾。

## 6. 攻击速度适配

攻击速度变化不能只缩短冷却。至少需要同步以下内容：

- 各动画阶段分配的 tick 数。
- GeckoLib 控制器播放速度。
- 伤害或投射物事件帧。
- 音效、粒子和武器显隐帧。
- 允许转火、允许取消和正式承诺的边界。
- 下一次攻击最早开始时间。

推荐把一个完整攻击间隔拆成阶段预算，然后按源动画长度计算播放速度：

```text
controllerSpeed = sourceAnimationTicks / allocatedStateTicks
```

例如源动画为 12 tick，而当前攻速为这个阶段分配 8 tick，则播放速度为 `12 / 8 = 1.5`。开火事件也必须按同一比例落到新的服务端 tick，而不是仍使用旧的固定数值。

限制：

- 设置最短阶段时间，避免一帧内跨越多个重要事件。
- 极高攻速下可以减少瞄准等待，但不能跳过取弹、开火和收尾的顺序约束。
- 若动画末帧需要 Hold，播放速度只影响到达末帧的时间，不影响服务端等待的安全性。
- 多段攻击应分别缩放每一段，而不是只缩放整套连招的总时间。

## 7. 控制器和骨骼所有权

推荐的职责划分：

- `movement`：待机、行走、普通跳跃和基础下半身运动。
- `action`：攻击、射击、技能、收武器和不可打断动作。
- 专用 `pose`：举盾、持续架势等可以和其他动作明确组合的状态。
- 渲染器代码：头部注视、瞳孔、眉毛、眨眼以及必要的父骨骼补偿。

每根重要骨骼在每个动作中必须知道由谁拥有。尤其需要检查：

- 根骨和主体骨是否同时被 movement 与 action 写入。
- 上半身攻击是否意外带入腿部关键帧。
- 全身攻击结束时，底层行走动画正处在哪个步态相位。
- 武器、箭矢、盾牌和粒子锚点是否跟随正确的父骨骼。
- 代码驱动头部是否正确抵消攻击姿势的父链旋转。

动作层停止时，底层动画会立即重新可见。即使动作末帧正确，底层当时的姿势与末帧差异过大仍会出现跳变。需要时可以让移动控制器在动作边界短暂锁定中立帧，再在完整游戏 tick 后释放。

## 8. 首帧、末帧、显隐和缩放

模型交付验收不能只观看动画主体。每个一次性动作都要检查：

- 首帧是否与所有合法前置状态兼容。
- 末帧是否与所有合法后继状态兼容。
- 动画长度字段是否覆盖最后一个关键帧。
- 末帧之后是否需要 Hold。
- 武器或弹药骨骼在首尾帧的缩放是否明确。
- 使用隐藏或缩放到零时，模型原点是否会短暂出现物体。
- 从箭袋、刀鞘或背部取物时，物体是否始终在正确的手或父骨骼下。
- 连续播放第二次时，所有临时骨骼是否从可预测状态开始。

不要依赖“未写关键帧就会自动保持正确状态”。不同控制器、前一动画缓存和默认模型姿势可能给出不同结果。关键的武器显隐、缩放与交接姿势应显式定义。

## 9. Hurt 与动作优先级

实际受到伤害和播放全身受伤动画是两件事。

- 伤害、击退、仇恨和自卫逻辑始终正常执行。
- 已承诺的近战、射击、连招和后撤步动作默认不能被全身 `hurt` 覆盖。
- 攻击期间仍可播放代码驱动的眨眼、表情和伤害来源注视。
- 若近战威胁要求立即反击，应由服务端状态机显式切换到不可打断近战，而不是等待 hurt 动画结束。
- 一个动作能否被另一个动作打断必须列在动作定义中，不能依赖调用顺序偶然决定。

## 10. 朝向与视觉系统交接

战斗期间身体、头部和瞳孔必须注视当前承诺目标。自然观察、主人对视、随机歪头和环境注意不能抢占战斗目标。

动作结束时也要处理视觉交接：

- 最后目标死亡后先进入短暂战斗收尾，不立即看主人又立即看回前方。
- 移动开始时，战斗注视直接交给前进方向。
- 客户端从精确战斗父链补偿切换回普通头部补偿时应平滑混合。
- 头部抽搐与手臂抽搐可能来自不同控制层，日志必须区分动作骨骼和注视骨骼。

完整的头部、瞳孔和自然观察规则见 `docs/VISUAL_BEHAVIOR.md`。

## 11. 标准诊断日志

日志应只在动作边界附近短时开启，避免持续刷屏。

### 服务端动作日志

至少记录：

```text
entityId
gameTick
event=start / retarget / release / hit / finish / cancel
action
previousAction
targetId
targetAlive
actionStartedAt
actionEndsAt
eventTick
playbackBudget
transitionReason
```

### 客户端骨骼日志

至少记录：

```text
entityId
gameTick
renderAge
action
previousAction
targetId
controller context
bone rotation
bone translation
bone scale
bone hidden / childrenHidden
largest per-frame delta
```

重点骨骼通常包括根骨、上下身、头部、左右大小臂、双腿、武器、弹药和粒子锚点。

### 判断方法

1. 先从服务端日志定位动作开始、事件和结束 tick。
2. 查看源动画在这些 tick 对应的真实时间。
3. 检查动作自然结束前后至少 5 tick 的客户端骨骼采样。
4. 如果动作状态没有改变但骨骼突然进入另一动作姿势，优先怀疑控制器缓存回放。
5. 如果状态改变后才跳变，检查首尾姿势、底层控制器和同步边界。
6. 如果只有物体闪现，检查缩放、显隐和父骨骼，而不只检查手臂旋转。

## 12. 新角色必测场景

每个拥有战斗动画的新英灵至少测试以下场景：

- 单目标连续攻击 20 次以上。
- 多目标存在时连续转火。
- 目标在起手前死亡。
- 目标在蓄力或取弹途中死亡。
- 目标在攻击已经释放后被投射物击杀。
- 最后一个目标死亡后完整退出战斗。
- 新目标在收尾期间进入范围。
- 近战威胁在远程攻击各阶段逼近。
- 攻击中连续受到伤害和击退。
- 行走、后退、跳上一格台阶和贴墙时攻击。
- 动作结束时正在行走或刚好停止。
- 最低、基础和最高计划攻速。
- 低帧率、较高帧率以及服务端短暂卡顿。
- 第一人称观察、第三人称观察和另一客户端观察。
- 武器、盾牌、箭矢及附属粒子骨骼的连续两次播放。

视觉验收标准：任何状态边界都不应出现与当前或下一合法动作无关的单帧姿势；武器和弹药不得出现在模型原点；动作结束后不得冻结在非预期姿势。

## 13. 实现与评审清单

提交新角色或新动作前确认：

- [ ] 动作阶段、持续时间、事件帧和打断规则已经明确。
- [ ] 服务端状态持续期间始终有合法动画姿势。
- [ ] Once／Loop／Hold 选择与服务端状态长度匹配。
- [ ] 不会对已经自然结束的 `PLAY_ONCE` 盲目重复停止。
- [ ] Hold 在状态结束时能够被可靠清理或替换。
- [ ] 伤害与投射物事件只执行一次。
- [ ] 目标死亡不会重新播放攻击第一帧。
- [ ] 高威胁转火不会重置当前攻击进度。
- [ ] movement 与 action 的骨骼职责没有未审查的重叠。
- [ ] hurt 不会覆盖不可打断动作。
- [ ] 攻速变化同步缩放动画和事件帧。
- [ ] 首尾姿势、武器显隐、缩放和父子关系通过验收。
- [ ] 战斗头部与自然视觉系统的交接没有跳变。
- [ ] 已完成标准边缘场景测试。
- [ ] 必要的短窗口诊断日志可以按实体和动作快速筛选。

## 14. 何时修改本规范

出现以下情况时应更新本文档，而不是只在单个角色代码中留下补丁注释：

- 新发现一种可复现的控制器或渲染边界抽搐。
- 更换 GeckoLib 版本后动画停止、保持或混合语义发生变化。
- 引入新的通用控制器层或共享战斗状态机。
- 攻速系统、动画事件系统或模型导出流程发生结构变化。
- 某个角色修复可以被后续角色直接复用。

纯角色美术选择、角色独有技能表现或单个骨骼映射不需要提升为全局规则。
