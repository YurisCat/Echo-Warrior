## 已确认或高概率为 BUG

| 用例 | 判断 | 依据与影响 | 处理范围 |
| --- | --- | --- | --- |
| EW-077 | 已确认 BUG | 知识书返还使用了普通背包插入后再检查剩余数量。创造模式满背包时，原版插入逻辑会把待返还物品数量清零，导致既没有进入背包，也没有掉落。违反“背包满时掉在玩家脚下”的项目约定。 | 改用原版“放回背包，否则掉落”流程。 |
| EW-101 / EW-102 / EW-103 | 高概率同一 BUG | 创造模式物品栏直接把饰品、护符或模块塞进召唤器时，客户端会更新物品，但服务端只收到创造栏位同步包，没有执行召唤器正常点击路径中的绑定状态提交。随后权威绑定数据把召唤器覆盖回旧状态，而鼠标上的物品已经减少，表现为吞物。 | 在服务端接受创造模式栏位更新后，若栏位物品是召唤器，立即提交其物理组件状态并同步已绑定英灵。 |
| EW-180 | 已确认 BUG | 埃及弓箭手使用独立跟随逻辑，超过距离后直接传送到主人当前 Y 坐标，没有验证脚下是否可站立。玩家在空中时会把弓箭手传进空气。 | 所有英灵召回和远距跟随统一只使用安全落点。 |
| 创造飞行高空抽搐/闪现 | 已确认与 EW-180 同类 BUG | 埃及弓箭手会在高空被反复传送、下落，再次超过阈值后又传回；其他英灵在主人悬空且没有可达落点时仍持续寻路或尝试传送，也可能出现位置抖动和不必要的路径计算。 | 主人明显悬空时停止向空气寻路；若英灵已在主人下方附近，则稳定等待；水平距离过远时最多按节流频率寻找主人投影附近的地表安全落点。 |
| 召唤器 GUI 英文缺失 | 已确认 BUG（开发自查） | 语言文件中虽然已有技能英文，但英雄名、属性提示、行动/警戒模式、经验、燃料、按钮及反馈文字大多直接硬编码为中文，切换英文后仍显示中文。埃及弓手的警戒范围提示还固定写成 16 格，与界面数值 24 格不一致。 | 全部改为中英文语言键；英文采用精简按钮与说明；标题、分区标题和按钮仅在实际超宽时等比缩小；警戒范围提示读取英雄实际范围。 |
| 日本武士表情系统缺失 | 已确认 BUG（开发自查） | 日本模型已经具备 `Head`、左右眼与 `Eyebrow` 骨骼，但实体没有同步注视、眨眼、对视及被发现偷看状态，渲染器也没有消费这些骨骼，导致第五位英灵明显缺少其他英灵已有的视觉生命感。 | 复用中国关刀战士的服务端视觉状态机，并增加日本模型专用客户端骨骼映射；战斗动作保留原动画骨骼优先级，残影只冻结最终姿势。 |
| 创造模式红叉销毁召唤器后遗留英灵 | 已确认 BUG（EW-100 测试过程中发现，但不是 EW-100 原步骤；Shift 批量清空追加复现） | 创造模式销毁槽不会生成掉落物实体；单个销毁旧实现无法取得被清空前的召唤器 UUID。首轮补丁虽能上报 UUID，但 Shift 点击红叉会连续清空整个创造栏，自定义确认可能在整批槽位同步尚未全部记账时提前结算，仍会漏掉部分对应英灵。 | 客户端仅在红叉实际销毁时上报递归取得的 UUID；服务端将请求短暂排队，从下一 tick 起在 40 tick 窗口内等待整批槽位更新，并再次确认 UUID 已真实移出且没有出现在任何在线玩家物品栏或光标后才遣散实体。原版 `CONTAINER` 与收纳袋嵌套内容一并处理；未知模组自定义容器继续优先避免误杀。 |
| EW-153 / EW-154 | 已修复，等待游戏内回归 | 原实现每个世界 tick 都把生命恢复 I 从 39 tick 刷回 40 tick，无法进入原版 I 级效果的 50 tick 治疗刻；粒子又被隐藏，因此既没有可靠回血也没有可见反馈。现改为饰品自有的 50 tick 服务端治疗周期，每次额外恢复 1 点生命，并只在生命实际增加时显示两颗轻量爱心粒子。 | 分别验证白天花冠、夜晚月露瓶、昼夜边界、同时安装、重登、满血状态和外部生命恢复药水；确认不双重治疗、不空放粒子，也不添加或覆盖原版状态效果。 |

## 运行日志观察

- 没有发现与上述失败用例直接对应的崩溃、异常堆栈或模组致命错误。
- 多次 `large_dripstone` 在远处未加载区块写方块失败，来源更像原版环境/世界生成行为，不足以指向 Echo Warrior。
- Realms、用户属性请求错误属于网络或账号环境噪声。
- JEI 对可选 Amecs 兼容项的提示不是本模组功能故障。
- 重复召唤器 UUID 警告出现多次，但随后有重分配行为；当前应视为防御性修复记录，而非崩溃问题。
- 原始 `latest.log` 约 5.2 MB、覆盖约两小时，包含大量动画与骨骼相关 INFO 输出。该发布质量风险已在 `0.1.0-test.20260901.1` 收尾：关刀动画诊断恢复默认关闭，埃及弓箭手的动作、注视和骨骼诊断统一降为 DEBUG。
- 2026-09-01 对 `0.1.0-test.20260901.1` 执行 EW-010 启动基线：Java 25 干净构建通过，开发客户端加载 53 个模组并快速进入 `CATTEST`；从 13:32:40 启动到 13:34:14 观察结束，`latest.log` 为 13,569 字节，Echo Warrior 只输出一次初始化 INFO，关刀与埃及诊断标签均为 0。日志中的登录阶段 ERROR 来自离线开发账号请求 Mojang 用户属性和 Realms 失败，另有原版空声音事件警告，均未指向模组。由于 Windows 自动化层拒绝接管 Java 游戏窗口，本次未冒充完成“打开 GUI、召唤与主动战斗”三项人工交互，因此 EW-010 的启动、资源加载和默认日志静默部分通过，完整交互基线仍需在测试客户端补跑后再最终标为通过。
- 日志没有记录阿兹特克勇士的攻击开始、命中帧距离或挥空原因，也没有对应异常堆栈；EW-222 的具体机制主要由测试现象与攻击代码共同定位，现有日志不能量化每次无法还手时的目标距离。若数值调整后仍不稳定，可临时记录攻击开始／命中帧的水平距离、原版近战范围检查结果与受击位移。

EW-153 / EW-154 已按饰品自有生命回复机制修复：白天花冠或夜晚月露瓶每 2.5 秒额外恢复 1 点生命，实际恢复时显示两颗轻量爱心粒子，不再伪装成或覆盖原版生命恢复效果。下一项优先检查 EW-021；该项缺少阻塞原因和实际结果，应先本地按 44 页／五章节步骤复测。EW-292 是把召唤器内部遗物误当作回收箱输入，不修改回收规则。
