# Echo Warrior 多版本移植与防回退手册

## 1. 目的

本文档保存能够跨 Minecraft 版本、加载器或依赖版本复用的移植经验。它回答的是：

- 某类问题为什么会在旧版本再次出现。
- 移植时必须检查哪些语义、资源和生命周期差异。
- 哪些检查应当自动执行，哪些必须由人观察。
- 修复一次之后，怎样避免在下一条兼容线重新踩坑。

本文档不是玩法设计来源、版本更新日志或逐次 Bug 流水账。

## 2. 文档职责边界

| 载体 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| `PROJECT.md` | 当前玩法规则、范围、依赖、兼容目标和已批准决策 | 详细调试过程和每次失败尝试 |
| 本手册 | 可复用的移植根因、规则、检查方法和版本差异 | 当前候选包状态和面向玩家的发布说明 |
| `scripts/check-<version>-baseline.ps1`、GameTest、自测命令 | 可确定、可重复的机器检查 | 画面、声音和手感判断 |
| `docs/COMPATIBILITY_<version>_TEST_CHECKLIST.md` | GUI、动画、声音、操作手感、真实多人等人工签收 | 代替自动构建或服务端状态断言 |
| `CHANGELOG.md` | 对外发布时值得玩家知道的变化 | 内部测试版本的完整诊断历史 |
| 回声档案馆 | 玩家可见的玩法、控制、数值和状态规则 | 纯工程迁移方式和内部工具变化 |

任何玩家可见规则都以 `PROJECT.md` 为准；本手册不得自行扩大玩法范围。

## 3. 什么时候维护本手册

修复 Bug 后，满足以下任一条件时，必须在同一任务更新本手册：

- 根因可能在另一 Minecraft 版本、另一加载器或另一依赖版本再次出现。
- 目标加载器（Fabric、NeoForge 或 Forge）的生命周期、网络、注册或客户端接口存在实质差异。
- 问题涉及保存数据、服务端权威、菜单并发、实体代次或跨维度状态。
- 问题涉及资源目录、模型格式、渲染批次、Mixin、类加载或专用服务器安全。
- 表面症状与真正根因差距较大，未来容易误诊。
- 同类问题已经发生过回归，或者仅靠代码审查很难确认。
- 修复形成了新的自动断言、GameTest、专服自测或人工复测规则。

以下情况通常不写入本手册：

- 单纯错别字、一次性版本号或没有迁移价值的局部重命名。
- 尚未复现、尚未定位根因的测试员描述。
- 临时诊断日志、失败实验和最终没有采用的方案。
- 只影响某一个内部候选包、且不会改变以后移植决策的打包失误。

未定位的问题先进入对应版本的人工测试清单或问题记录；根因确认后再决定是否沉淀到这里。

## 4. 每个 Bug 的维护决策

每次确认并修复一个 Bug，按以下顺序处理：

1. **当前规则是否改变？**
   - 是：更新 `PROJECT.md`。
   - 若同时改变玩家可见玩法、控制、平衡值或状态，再更新回声档案馆。
2. **根因是否可跨版本复用？**
   - 是：更新本手册对应条目；没有合适条目时新增。
3. **能否由机器稳定判断？**
   - 能：增加或更新基线脚本、单元测试、GameTest、自测命令或集成测试。
   - 不能：把最短、可复现的观察步骤加入人工清单。
4. **是否影响对外交付？**
   - 是：在正式发布时更新 `CHANGELOG.md`。
5. **是否只是当前候选包的修复历史？**
   - 是：放在对应版本状态记录中，不把整段调试过程复制到本手册。

因此，维护策略不是“每发现一个 Bug 就无条件向本手册追加一段”，而是“每次修复都执行一次分类，自动维护真正有长期价值的部分”。

## 5. 新增经验条目的最低格式

新增或扩充条目时至少写明：

- **症状**：玩家或测试端实际看到什么。
- **根因**：哪个版本、加载器、生命周期或权威边界造成问题。
- **移植规则**：以后应当做什么，不能只写这次改了哪个类。
- **自动守卫**：由哪个脚本、测试或 JAR 审计检测；没有时写“暂无”。
- **人工签收**：仍需观察哪些画面、声音、手感或多人行为。
- **适用范围**：共享规则、特定 Minecraft 版本、加载器或依赖版本。

推荐格式：

```markdown
### PORT-XXX 简短标题

- 症状：
- 根因：
- 移植规则：
- 自动守卫：
- 人工签收：
- 适用范围：
```

已有条目能够覆盖新问题时，优先扩充原条目，不制造重复条目。

## 6. 固定移植流程

### 6.1 开始之前

1. 阅读 `PROJECT.md`、本手册和目标版本 README。
2. 明确主线版本、目标版本、两个加载器、Java 和依赖版本。
3. 建立功能清单，而不是按文件名机械复制。
4. 标出玩家可见功能、服务端状态、客户端表现、资源和数据五个层面。
5. 确认目标版本是否需要独立存档和运行目录；默认不得把高版本世界降级打开。

### 6.2 推荐实施顺序

1. 构建系统、加载器元数据和专用服务器安全。
2. 注册表、数据组件或旧版等价存储、菜单和网络通道。
3. 保存数据、UUID、绑定代次和跨维度恢复。
4. 一条完整纵向切片：物品 → GUI → 实体 → AI → 战斗 → 动画 → 保存。
5. 公共玩法系统与其他英雄。
6. 模型、动画、纹理、声音、本地化、配方、标签和创造栏。
7. 自动基线、专服自测、经授权的客户端启动检查和人工签收。

### 6.3 完成定义

一条兼容线只有同时满足以下条件才算完成：

- 两个加载器从同一候选版本构建出独立 JAR。
- JAR 内只包含对应加载器元数据，不混入另一加载器入口。
- 专用服务器能够启动、自测并正常关服。
- 注册、保存、网络和权威状态有自动断言。
- 玩家可见资源与本地化经过 JAR 内容审计。
- 画面、声音、控制和多人体验有明确的人工清单。
- 已解释所有主线独有文件：是功能遗漏，还是目标版本格式不适用。
- 没有把自动测试通过误写成人工观感已经签收。

## 7. 固定审计矩阵

每次新增兼容版本或同步完整功能节点时，至少检查以下项目。

### 7.1 构建与加载器

- Java 字节码版本与目标运行时一致。
- 目标加载器元数据、入口点、依赖和客户端入口互不串包；不能把 Forge 与 NeoForge 当作可互换的发行标签。
- 共享类不直接引用只存在于某一加载器的 API。
- 客户端类和客户端 Mixin 不会被专用服务器加载。
- 构建、运行目录、日志和测试世界与其他版本隔离。
- 目标使用生产重映射时，审计并运行最终发行 JAR 而非开发 JAR；1.20.1 Forge 必须验证 SRG 重映射、非空 refmap 和 `MixinConfigs` 清单。开发启动成功或 JSON 存在不代表生产注入生效。

### 7.2 注册与内容目录

- 物品、方块、方块实体、菜单、实体、声音、粒子、创造标签均已注册。
- 创建了对象不等于玩家可取得：同时检查创造栏、配方、战利品、交易或命令入口。
- 注册数量、稳定 ID 和文化/稀有度/生物群系标签与主线功能清单一致。

### 7.3 资源与本地化

- 模型、纹理、动画、声音、技能图标、状态图标和字体使用目标版本支持的格式。
- 中英文键集合和值按需要比较；同时审计代码真实调用点、描述行数和状态分支。
- 资源存在不代表渲染可见：颜色提供器、透明层、绘制层级和批次提交单独检查。
- 主线独有资源文件必须逐项解释，禁止仅凭目录差异认定遗漏。

### 7.4 网络、菜单与创造模式

- 服务端对物品、绑定、燃料、技能、饰品和模式拥有最终权威。
- 客户端预测只提供即时观感，不得成为最终保存来源。
- 菜单保存多个关联槽时应原子提交，不能分次写回互相覆盖。
- 长时间打开的菜单必须检测服务端状态修订，拒绝旧状态覆盖新状态。
- 创造物品栏的包装槽、快捷栏映射和垃圾槽必须单独测试，不能假设与生存菜单一致。

### 7.5 保存与实体生命周期

- 物品容器组件和世界 SavedData 的权威关系明确。
- UUID 重复、实体代次、未加载实体、跨维度恢复和旧投射物失效均有测试。
- 修改 schema 前明确是否支持已公开存档；内部开发世界可以重建时必须写清。
- 失败事务能够回滚物品、燃料和绑定状态。

### 7.6 AI、战斗与动画

- 服务端命中时刻、朝向、动作状态与客户端动画使用同一时间预算。
- 不同 GeckoLib 版本必须核对触发动画、速度、累计时间和过渡语义。
- 动画首尾帧连续不等于状态切换连续；仍需检查时间轴倒拨和空档。
- 视觉注视、程序化骨骼与模型动画的父骨骼补偿按目标模型重新验证。
- 自动测试验证状态和伤害，人工测试验证抽搐、衔接、速度与观感。

### 7.7 GUI 与视觉反馈

- GUI 原始纹理尺寸、缩放、容器坐标和屏幕绝对坐标不得混用。
- 工具提示应在所有图标之后绘制，保持最高层级。
- 自定义粒子、斜光和覆盖层必须检查深度、批次刷新及实际目标槽坐标。
- 物品渲染与落地方块可能具有不同世界上下文、朝向和初始化时机。
- 自定义消息、动作栏、标题抖动和淡出等反馈需检查是否重复显示原版版本。

## 8. 已确认的可复用经验

### PORT-001 本地化资源齐全不代表界面已经迁移

- 症状：资源文件中存在中文和英文文本，游戏仍显示翻译键、缺少描述或行数不完整；Shift 展开提示也可能遗漏当前装入的英灵等运行时状态。
- 根因：兼容界面没有调用对应键、使用了过时键、描述行数仍按旧实现读取，或只迁移静态说明而遗漏空/非空等状态分支。
- 移植规则：同时比较语言文件键值和所有玩家可见调用点；状态型技能和物品提示必须覆盖每个状态分支，并把当前权威物品组件转换为本地化名称。
- 自动守卫：跨版本双语键比较、源码调用点、状态分支和描述行数断言。
- 人工签收：悬浮全部技能、天赋、状态、按钮及空/已装入状态物品，检查换行与层级。
- 适用范围：所有版本和加载器。

### PORT-002 注册、资源、取得入口必须作为一个整体迁移

- 症状：物品类存在但创造栏不可见，或进入游戏后出现紫黑格、无配方、无标签。
- 根因：只迁移 Java 注册，遗漏模型、纹理、创造标签、配方、战利品或交易入口。
- 移植规则：按稳定内容 ID 建立清单，逐项覆盖注册、资源、本地化、配方、标签和取得路径。
- 自动守卫：JAR 内容清单、注册数量、配方和标签解析。
- 人工签收：创造栏分类、配方书、交易和实际掉落。
- 适用范围：所有内容型移植。

1.20.1 Forge 注册时机补充：菜单工厂在模组构造器中赋值时，如果字段与静态 Item 位于同一内容类，会连带触发物品创建，导致 `Registry is already frozen` 启动失败。共享类的静态初始化依赖也属于注册生命周期；工厂创建与引用应放到对应 `RegisterEvent` 内，不能只看最终 `register` 调用的位置。Fabric 使用自己的菜单工厂，不把加载器扩展的可见性当成 vanilla API。自动守卫是两个生产包的真实启动及注册/菜单自测；人工仍需从物品进入实际界面。已确认于 1.20.1 Forge 47.4.10，其他版本按各自注册阶段核对。

PORT-002 的 1.20.1 方块实体补充：原版 `BlockEntityType.Builder` 的工厂参数类型在共享编译环境不可访问，Forge 的访问扩展不等于 Fabric/common 也支持。回收箱工厂分别在加载器注册阶段用 FabricBlockEntityTypeBuilder 或 Forge 扩展创建。自定义考古方块保留原版 brushable 类型时，必须扩展该类型对自有方块的合法性检查，否则创建成功仍可能无法正常 tick/载入。自动守卫覆盖回收事务、生产 refmap、两端启动及原版刷取/NBT 回读；人工仍观察卡扣、刷取阶段和掉落。适用于 1.20.1 双端，新增版本重新核对 API。

PORT-002 的 1.20.1 知识创造栏补充：注册 40 种带 NBT 的碎片不等于迁移了完整合集的取得入口。知识页第一格必须是含 40 个不同条目、各一份且书签为第一页的合集，其后按固定顺序显示 40 个碎片，页签图标也使用合集。`BooksSelfTest1201` 对实际注册页签执行 `buildContents`，检查数量、顺序、内容与书签；人工仍验打开合集及翻页。只补既有入口，不修改合成规则。

### PORT-003 依赖版本决定资源目录和动画语义

- 症状：召唤实体后客户端崩溃、模型缺失，或动画在状态切换时倒拨和抽搐。
- 根因：GeckoLib 5 与 GeckoLib 4 的资源目录、控制器速度和累计时间处理不同。已确认的 1.21.1 GeckoLib 4.9.2 问题还包括：速度乘以从动作开始累计的时间，按同步阶段改变速度会倒拨整段时间轴；动画触发包可能先于阶段时长同步到达；释放与收箭误用另一段资源时长；单帧瞄准循环和本已连续的动画接缝额外插值造成重复过渡。
- 移植规则：按目标依赖源码和文档适配；1.21.1 GeckoLib 4.9.2 使用 `assets/<modid>/geo/` 与 `assets/<modid>/animations/`，不能机械复制高版本加载路径。搭箭、拉弓使用完整序列并保持末帧，不另起循环瞄准动作；每次触发按自身资源时长与稳定动作预算确定速度，不能依赖迟到的阶段字段而中途改变时间基准。只有确认两个片段逐骨骼首尾连续后，才移除多余过渡，不能对全部英雄一律关闭插值。换用 GeckoLib 4 的其他小版本也要重查实现，不能因主版本相同跳过验证。
- 自动守卫：`scripts/check-1.21.1-baseline.ps1` 的 JAR 路径、完整搭箭/拉弓保持序列、按触发动画选速度、独立释放/收箭预算、控制器过渡及诊断入口断言；动作状态自测。排查时将服务端阶段/预算与客户端触发动画/实际速度/累计时间关联，不把没有异常日志当作动画正确。
- 人工签收：首次动作、连续动作、释放瞬间、收势和转火。
- 适用范围：已在 1.21.1 GeckoLib 4.9.2 确认；跨 GeckoLib 主版本及可能改变控制器语义的小版本时复用检查方法，不假定底层算法完全相同。

1.20.1 GeckoLib 4.8.4 补充（2026-09-20）：

- 症状：召唤器预览中的五名英灵双手/武器反复抖动；世界内关刀连招收势出现整身翻转。
- 根因：GUI 创建的独立实体不接受世界 tick，`tickCount + partialTick` 因插值回绕而倒退。关刀连招末帧使用等价的三轴约 ±180° 表示，待机/行走没有为 Main 写旋转轨道；动作控制器零过渡并不能关闭动画处理器默认五 tick 的未驱动骨骼复位，也不能阻止行走控制器从动作层快照开始插值。
- 移植规则：预览只推进动画年龄，不执行完整实体 tick/AI，不把预览加入世界。检查动作结束后的每个父骨骼由谁接管；仅针对已核对端点的动作补待机根姿态，并在动作交接短窗口避免跨 Euler 分支插值。不得把所有英雄/所有动作全局改成零过渡。
- 自动守卫：`HeroMenuClientSelfTest1201` 对五英雄各检查 40 tick 的预览年龄与实体身份/世界隔离；`GuandaoPresentationClientSelfTest1201` 用实际 GeckoLib 处理器和发行资源推进连招，检查停步/立即行走及动作状态相对停止包早到/同步/晚到三种顺序。资源基线只允许 idle/walk 的 Main 零旋转差异，其余连招数据必须与源资源相同；破坏性副本测试验证守卫会拒绝缺轨/改连招的包。
- 人工签收：五英雄预览连续观察，关刀多次连招后停步/行走/立即继续战斗；自动骨骼断言不替代整体动作观感。
- 该次确认范围：1.20.1；1.21.1 的后续同步与验证见下文，不能把旧版证据当成另一 GeckoLib 小版本的验收。

1.21.1 GeckoLib 4.9.2 收招翻转补充（2026-10-07）：

- 症状：Fabric 0.2.3 的关刀四段连招结束后，以脚部为中心短暂整身翻转。FOXY-NODE 修复前客户端的实际处理器测试在 tick 112 检出 Main 旋转 `(3.1415927, -3.1580706, 3.1415927)`，与缺失接管轨道及五 tick 复位路径相符。

### PORT-006 关联菜单状态必须原子提交并带修订号

- 症状：取出饰品后关闭 GUI，重开又出现原物品；关闭的技能被旧菜单恢复；两个关联槽互相覆盖。

- 人工签收：多人同时修改、关闭重开和重进服务器。

1.20.1 存储适配补充：组件降级为可变 `CompoundTag` 时，读取不得通过 `getOrCreateTag` 隐式改动物品；读出的子物品和写入载荷必须独立复制，完整八槽先校验再提交。`SummonerStorageSelfTest1201` 已覆盖旧快照不得恢复取出的物品、失败写入不变、相同内容不增加修订、其他 NBT 保留及物品网络包往返。这些是存储原语守卫，尚不能代替未来服务端世界绑定与真实菜单点击测试。

已确认的旧 NBT 陷阱：1.20.1 `ItemStack.of(CompoundTag)` 新建物品栈，但其构造器直接保留嵌套 `tag` 引用，且载入时可能规范化耐久/调用物品校验；新建 ItemStack 不等于深拷贝。对存储条目执行 `ItemStack.of(entry.copy())` 后才能交给可修改的菜单或只读容器扫描。仅测试 `shrink` 改数量发现不了这个问题；自测必须修改子物品 NBT 并断言原存储不变，另用非法耐久条目证明扫描本身不重写源 NBT。该规则适用于 1.20.1 Fabric/Forge 旧 NBT，不能未经核对推广为新版组件实现的内部细节；人工仍需签收真实菜单的技能/遗物状态保存。

1.20.1 菜单状态号补充：新增严格过期点击检查后，曾出现“取到鼠标后，放回背包被拒绝”。根因是原版 `ServerPlayer` 的 cursor 同步递增 `stateId`，但 `ClientPacketListener` 对容器编号 `-1` 的包只设置鼠标栈，不更新菜单状态号；原版处理过期点击也只是执行后全量同步，并非拒绝事务。移植规则：服务端先验证菜单状态号和世界修订；客户端仅针对本模组菜单补齐 cursor 状态号，不放宽旧请求校验、不影响其他容器。一次点击结束后才提交八槽，关闭菜单不保存旧副本；燃料物品扣减与能量增加也应共用一次权威修订。自动守卫：`SummonerMenuSelfTest1201` 验证槽位锁、存取、过期状态、重开和原子燃料转换，`MenuClientSelfTest1201` 经真实 use/open/click 包连续取放并故意发送过期包；后者专门覆盖“服务端直接调用全通过、真实客户端才失败”的缺口。人工仍需确认连续快速点击、不同延迟、拖拽与多种 GUI 缩放。已确认于 1.20.1 Fabric/Forge；不要未经检查假定新版 cursor 包语义相同。

1.20.1 遗物/饰品适配补充：同一遗物的等级、技能和冷却变化不能被当成换遗物；真正取出或替换遗物又必须让旧代绑定立即失效。菜单的装备事务按物品类型与稳定遗物 ID 区分这两种情况，将八槽更新和旧绑定失效合为一次修订；实体移植阶段还须消费这一失效状态并清理实体，不能宣称单凭数据失效已经验证英灵消失。饰品去重按注册物品类型，不使用包含自定义名称/NBT 的堆叠相等规则。旧 NBT 的更新先修改独立副本，成功且内容改变才替换源 tag；重复初始化、只读 tooltip、无变化及失败更新不得造成状态刷新。`RelicEquipmentSelfTest1201` 覆盖保留外部 NBT、一次初始化、22 类天赋互斥、五英雄成长/箭型/充能、改名重复拒绝、六槽存取、换遗物失效与两次真实存档启动；`MenuClientSelfTest1201` 覆盖实际网络下取回饰品/遗物和关闭重开。适用于 1.20.1 双加载器旧 NBT 与装备权威边界；人工仍需签收 tooltip、快速操作及未来真实英灵离场。

### PORT-008 GUI 可见性取决于最终绘制批次

- 症状：日志证明斜光或粒子已经创建并渲染，但屏幕上完全不可见；工具提示被技能图标遮挡。
- 根因：顶点进入了错误的深度层或共享批次，随后被物品图标覆盖；工具提示提交时机过早。反馈还曾在加载器初始化回调与当前界面判断之间丢失；已平移的容器坐标系再次使用屏幕绝对坐标则造成整体偏移。
- 移植规则：先刷新容器/物品批次，再用目标版本等价的无深度 GUI 覆盖层绘制并立即刷新；悬浮提示延迟到全部内容之后。反馈由当前界面消费有容量上限及过期时间的队列，避免初始化时机丢事件或残留到下一界面。明确锚点属于屏幕还是容器坐标，只转换一次。`enqueue → drain → render` 日志只证明执行路径，不证明最终像素可见。
- 自动守卫：`scripts/check-1.21.1-baseline.ps1` 检查队列消费/过期、绘制层、`flush`、召唤器透明度遮罩、目标槽锚点和工具提示最终绘制路径。
- 人工签收：不同 GUI 缩放、创造栏和普通容器中观察实际层级。

### PORT-015 物品组件同步不能被第一人称渲染器误判为换手

- 症状：手持教程手册或知识碎片集翻页，或手持召唤器同步燃料、遗物和饰品时，第一人称手臂反复下沉、抬起或重播使用物品动作。

- 人工签收：教程手册与知识碎片集在主手、副手连续翻页和切换章节，召唤器多类组件同步，以及真实换物动画。
- 适用范围：1.21.1 与 26.1.2 的 `ItemInHandRenderer`，以及未来使用组件同步的手持 GUI 物品。

- 自动守卫：`GuandaoPresentationClientSelfTest1201` 检查锚点存在、每层发射频率、同帧去重、多实体独立预算、满层火焰加火星和预览不消耗/不生成世界粒子；渲染器使用同一个受测预算实现。
- 人工签收：挥砍、连招、转身时刀刃贴合位置；一至五层密度和多名战士同时显示。调度断言不能替代真实发射位置观感。
- 适用范围：1.20.1 GeckoLib 4.8.4；1.21.1 有同源固定偏移代码，待单独同步验证；26.1.2 的 RenderPass 骨骼回调与旧版 API 不可直接互换。

### PORT-028 实体删除成功不代表消散表现已经执行

- 症状：解散或销毁召唤器后英灵确实消失，但没有灵魂消散粒子/音效；死亡时也缺少专属灵魂反馈。
- 根因：1.21.1 绑定系统八处实际移除路径直接调用 `livingEntity().discard()`，绕过五英雄现有的 `dismiss()`；两条低版本线仅继承原版死亡烟雾，没有死亡 SOUL 发射路径。实体消失和绑定失效的旧断言无法检出表现缺失。
- 移植规则：区分有反馈的解散/成功替换与静默回滚/未入世界实例清理。前者走英雄统一入口，不把所有 `remove/discard` 全局改成发特效。死亡立即注销绑定，但允许原版死亡姿势运行，在最终移除前由服务端发送一次粒子；客户端不重复发射，已删除实体不重播。
- 自动守卫：`DepartureEffectsSelfTest1201/1211` 经真实服务器发包路径捕获五英雄的物品解散、ID 解散、召唤器销毁、20 tick 死亡流程；检查 24 个 SOUL、实体中心位置、重复移除无包、普通生物和静默 discard 无包。1.20.1 还检查实际关刀四段音效包仅末击包含暴击且不含铁砧。两版本专服脚本要求成功标记；JAR 基线要求自测类，1.20.1 另核对 `tickDeath` 生产映射并用损坏包反例验证拒绝。
- 人工签收：五英雄分别观察主动解散、死亡、创造销毁召唤器的可见粒子位置和时机；附近另一名玩家应可见。低粒子设置可能压缩显示量，不以服务器包计数等同于视觉签收；关刀末击仍需听感确认。
- 适用范围：1.21.1 Fabric/NeoForge、1.20.1 Fabric/Forge；后续版本按各自死亡移除时机重审。26.1.2 本次未改。

### PORT-029 可替换方块不等于可清理植物

- 症状：雪原遗迹生成后地表积雪消失，厚雪处还可能被当作不合适地表。
- 根因：三个版本都把 `canBeReplaced`/REPLACEABLE 当作植被清除条件，而雪层也满足；较厚雪层可能进入高度图，使检查与实际放置错把雪层当作考古地表。
- 移植规则：区分“允许存在的覆盖物”和“应移除的植被”。雪层允许出现在候选场地，但清理时停止，不改层数；检查和放置统一以雪层下方的天然地表为准，完整雪块不作为可挖掘地表。只修后续生成，不猜测回填旧场地。
- 自动守卫：`ExplorationIntegrationSelfTest1201` 在真实双端专服中逐一铺设 1～8 层雪，经实际选址、放置及邻居更新检查积雪完整、6～9 个考古方块位于雪下；完整雪块拒绝且保持原样。专服和同包证据脚本要求该标记。`check-battlefield-snow.py` 检查三版本地表解析/清理/白名单的实现完全一致，且检查和放置都使用解析入口；该源码守卫不能替代其他版本的实际雪原观感签收。
- 人工签收：新生成的雪原遗迹不出现被抹去的雪片，厚度保持；清雪后可正常考古，草花场地仍可生成。旧遗迹不会自动补雪。
- 适用范围：26.1.2 Fabric/NeoForge、1.21.1 Fabric/NeoForge、1.20.1 Fabric/Forge，以及后续地表覆盖物生成。

### PORT-030 索引查询和方块移除事件不能退化为全世界轮询

- 症状：携带回声罗盘探索时 tick 入口耗时随存档扩大，且定期集中出现大量区块存在性检查。玩家报告的 Spark 入口百分比只代表采样期间聚合耗时，缺少子调用报告时不能直接当作已复现的罗盘独占耗时。
- 根因：1.21.1/1.20.1 兼容实现遗漏主线的空间查询和移除通知；锁定目标每刻遍历全部区域，范围搜索也扫全表，服务端另每秒遍历全部活动/清场位置，逐一查询是否加载。入口名和玩家归因容易掩盖独立的世界维护开销。
- 移植规则：按中心坐标计算区域键，用负坐标安全的 floor division；有限范围只查邻近区域，管理员全局定位独立遍历已有记录，不能把无限范围传给坐标网格循环。方块移除由目标版本实际 `BlockBehaviour.onRemove` 通知，不把刷取阶段变化或替换成另一考古方块当作完成。考古位置可跨区域边界，移除及加载纠错需查相邻区域；重载只读事件提供的已加载区块，不查全世界或加载邻区。新版本须重新核对移除方法名称、继承关系和加载器生产映射。
- 自动守卫：`check-battlefield-performance.py` 接入两条兼容基线，拒绝 gameplay 全表遍历、恢复全局方块轮询或罗盘区块访问。`BattlefieldPerformanceSelfTest1211/1201` 在隔离数据中加入一万条历史区域并禁止 Map 全表迭代，断言锁定目标 1 次、2048 格搜索 49 次查询、负坐标半径边界和跨区块归属；随后通过真实 `setBlock` 验证移除 Mixin、阶段更新不误完成、保底完成/剩余清场、重复通知、局部重载纠错和未加载目标保持。专服脚本要求成功标记；1.20.1 JAR 基线同时检查生产 `onRemove` refmap，实际发行专服验证注入执行。副机 `run-foxy-tests.ps1` 对当前文件和四个 JAR 核对 SHA-256，串行执行 `smoke-test-1.21.1-production-servers.py` 与 1.20.1 既有发行专服测试，确保开发映射通过不能掩盖生产 Mixin 失败；证据区分自测守卫与原整合包性能复现。
- 人工签收：原反馈整合包用相同玩家路线、视距和服务器设置复测持有/不持有罗盘，提供 Spark 子调用报告及 tick 尖峰对比；真实多人确认保底移除后的清场提示、指针和回响连续。自动查询次数断言不等于整合包毫秒改善或视觉/声效验收。
- 适用范围：1.21.1 Fabric/NeoForge、1.20.1 Fabric/Forge；26.1.2 已有局部查询和移除通知，本次不改其运行实现。适用于后续世界索引、方块生命周期和加载器移植。

### PORT-031 跨操作系统验收 JSON 资源时比较数据，图片比较字节

- 症状：Linux GitHub Actions 构建和审计通过的 1.20.1 正式包，Windows 副机基线误报 `Missing or divergent hero resource`；模型 JSON 实际内容完全相同。
- 根因：Git 的 `core.autocrlf` 使 Windows 检出源码为 CRLF，CI 包内文本为 LF；基线把模型、动画、考古、罗盘和知识目录 JSON 当作二进制逐字节比较。差异只在换行，不是资产或游戏行为改变。
- 移植规则：JSON 资源解析后比较完整数据树，保留数组顺序、字段、值和版本转换约束；PNG、音频及其他二进制仍逐字节核对。不能为了跨平台通过而忽略资源内容、跳过缺失条目或降低生产 Mixin/类检查。实际发行 JAR 的 SHA-256/SHA-512 仍比较完整原始字节。
- 自动守卫：`check-1.20.1-baseline.py` 的 `resource_matches` 用于原样继承 JSON；`test_compatibility_1201_baseline.py` 同时覆盖双端 JSON 格式/LF/CRLF 等价接受、几何标识/考古 blockstate/罗盘模型/知识目录数据变更拒绝，以及图片字节变更拒绝，当前共 47 项。副机可直接验收 CI 原包，不重打包或改写待发布 JAR。
- 人工签收：资源内容未变无需新增画面测试；若数据树或二进制素材实际改变，仍按对应模型/动画/GUI 人工清单验收。原始发布哈希与平台文件必须一致。
- 适用范围：1.20.1 Fabric/Forge 的资源审计；适用于所有 Windows/Linux 构建产物、Minecraft 版本及加载器的跨平台发布校验。

### PORT-032 高等级计算值需要同时审计属性实例与存档含义

- 症状：成长公式已支持高等级，实际最大生命仍被原版截断；降低服务器等级上限后再恢复可能永久损失培养，重新应用属性还可能误回血。
- 根因：属性最终值经过原版 RangedAttribute.sanitizeValue；原实现把配置上限同时当作存档上限、曲线分母和回收价值边界；旧兼容线保留“属性上升就补生命差额”的重应用分支。
- 移植规则：仅为英灵自己的生命/攻击 AttributeInstance 标记放宽上界，普通实体范围保持原样；存档培养等级、生效等级、固定成长分母与回收计价上限分别建模。降上限不改写保存数据；属性重应用保留绝对生命、仅在超过新最大值时截断。不要通过改全局注册属性范围解决单个模组的成长。
- 自动守卫：三线 `EchoProgressionSelfTest*` 用真实注册实体、已转换 AttributeInstance 检查 10000 生命/5000 攻击与普通实例仍封顶 1024；验证原 1305 经验边界、11385→100、1/30/100/1000/5000 上限、降再升保留级内经验、重应用不补血，菜单另见 PORT-025。各版本运行证据单独记录，不能用共享公式测试替代生产 Mixin 运行。
- 人工签收：高等级 GUI 排版、配置不同的远程服务器登录/退出、实际五英雄战斗与回血节奏。
- 适用范围：26.1.2 Fabric/NeoForge、1.21.1 Fabric/NeoForge、1.20.1 Fabric/Forge。

### PORT-033 外部宠物管理应桥接权威事务，并覆盖实际调用的重载

- 症状：本体每次重建分配新实体 UUID，外部列表产生遗失条目；直接恢复外部快照会绕过或被本体代次检查拒绝。联合测试还发现取消追踪会走第三方“先释放宠物”分支，而只按裸方法名注入时漏掉实际使用的三参数重载。
- 根因：第三方用实体 UUID/实体快照作为管理身份，本体用召唤器绑定和代次作为权威；两者不能互换。第三方同名重载与加载器网络上下文也并非相同 API。1.20.1 原事务另要求临时镜像先具有召唤器 ID，不能直接套用 1.21.1 的空输出缓冲。
- 移植规则：可选层派生稳定展示键，操作时重新查世界绑定、控制权、遗物和燃料，调用原事务；展示文件永不作为生成或回滚权威。取消追踪通过第三方删除入口清理索引和队伍，但在限定调用域跳过放出旧快照。注入需覆盖所有已核实重载；无参数捕获的同返回值重载可用 `methodName*` 并约束注入数量，避免在 `remap=false` 中硬编码跨命名空间的 Minecraft 描述符。见 [Mixin 官方通配目标说明](https://github.com/SpongePowered/Mixin/wiki/Advanced-Mixin-Usage---Callback-Injectors#62-wildcard-targets)。未安装第三方时不加载其类；不以源码分支代替正式 JAR 验证。
- 自动守卫：`EchoExternalCompanionSelfTest1201/1211` 在真实箱子、空背包条件下循环原事务 100 次，覆盖跨维度、缺失实体恢复、生命/燃料保持、权限、退款和失效绑定。`TbfJointSelfTest*` 装入固定 SHA-256 的发行包，通过实际列表、收放、队伍、治疗和取消追踪处理器验证单条目、队伍连续性、普通宠物透传与禁止快照恢复；测试启动参数要求适配成功启用和独立 PASS 标记。`TbfUntrackingMixin*` 要求两次注入，适配插件检查对应两个布尔重载。
- 人工签收：第三方列表/轮盘的实际点击与预览、多人控制权移交、断线重连及整合包组合。记录服务器自测范围，不把模拟连接收到包等同于真实客户端视觉验收。
- 适用范围：已核验 API 的 TBF 0.2.3：1.20.1 Forge、1.21.1 NeoForge；1.20.1 Fabric 0.2.2 仅为源码候选，仍需发行包联合验收。后续第三方版本或加载器必须重新核对签名和生产映射。

### PORT-034 构造尾部之间的属性 owner 时序不能依赖 Mixin 排序

- 症状：多模组 1.20.1 Forge 在召唤器创建英灵预览时抛出 `An AttributeMap object was modified without a set owner!`，而仅装本体和 Apothic 的最小组合可能通过。
- 根因：本体与 Apothic 都在 `LivingEntity.<init>` 尾部注入；本体先查询/标记成长属性时，惰性属性创建就会触发脏回调，Apothic 的 owner 尚未绑定。只删掉显式 `setDirty` 不能解决。完整包转换后的字节码与原版发行包实跑均确认该顺序。
- 移植规则：需要前一构造阶段完成的操作应移到有结构性先后保证的后续边界，不能只改 priority、吞异常或代写第三方 owner。当前 1.20.1 可选选择插件只读 Apothic `IEntityOwned` 字节码；存在时互斥选择 `Mob.<init>` 尾部的英灵成长初始化，不存在时保留原入口。插件置于 integration 包，不提前加载游戏/可选依赖类；成长范围计算、存档、网络与普通生物规则不变。
- 自动守卫：1.20.1 产物基线及损坏 JAR 测试检查选择插件和兼容 Mixin 注册/类；`EchoProgressionSelfTest1201` 用五种真实注册实体检查 10000 生命/5000 攻击，另测普通属性上限与重应用不回血。生产专服需有/无 Apothic 对照，客户端需使用固定哈希的失败整合包验证五英雄真实预览/召唤。原包缺陷与其他自测失败分开记录，不能把部分通过写成全套通过。
- 人工签收：整合包内反复换遗物、打开预览、召唤撤回及真实多人；修改 Mixin 后重启客户端/服务器，不需要新世界或新区块。
- 适用范围：确认于 Minecraft 1.20.1、Forge 47.4.20、Echo Warrior 0.2.4、Apothic 1.3.7。1.20.1 Fabric 共用选择插件，须验证缺席路径；1.21.1 和 26.1.2 未确认同一缺陷，不自动外推或同步修改。

## Windows 自动客户端收尾：控制台宿主生命周期（2026-10-07）

- 症状：实际测试检查点已通过，收尾时出现 cmd.exe /c exit -1 的 0xc0000142 窗口并遗留子进程；本轮涉及主线 NeoForge 与 1.21.1 两端。错误时间和清理阶段吻合，不等同于发行包运行错误。
- 已定位的脚本风险：按 PID 大小强制结束所有后代时，控制台宿主也被当成普通任务进程，可能早于正在连接的控制台子进程关闭。底层失败 DLL 未单独归因；不能写成 Windows 安装已损坏。
- 规则：自动路径保留启动器控制台，标准输出/错误继续记录；遍历 conhost/OpenConsole 的后代，但不要主动结束这两个宿主或系统代为显示对话框的 csrss。终止只限已观察到由本次任务创建的进程，退出后独立核验进程与错误窗口。
- 自动守卫：scripts/test-client-console-cleanup.ps1；本轮还完成了新的 1.21.1 Fabric 独立世界实机启动与收尾，零 cmd/Java 残留、零错误窗口。
- 边界：适用于 Windows 多版本/多加载器测试启动器，不改变模组或玩家退出语义。其他加载器和游戏仍使用相应实机验收，GUI 必须在节点已登录且解锁的会话进行。
