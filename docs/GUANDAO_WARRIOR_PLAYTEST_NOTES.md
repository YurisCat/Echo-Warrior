# 关刀甲胄战士：实机验收与模型师注意事项

更新时间：2026-08-26

这份文档记录关刀甲胄战士当前已经处理的问题、仍有必要实机确认的项目，以及后续模型更新时需要避免重新引入的动画风险。它不是新增需求清单；未明确列为待修改的项目只需要观察和反馈。

## 已处理并通过日志复查

- 普通攻击与四段连招结束后的可见抽搐目前未再复现。服务端动作按明确时限结束，GeckoLib 动作层使用零 tick 过渡释放，并始终以待机动画作为稳定的下层姿势。
- 连招结束瞬间，日志曾记录 `Main` 骨骼约 `180°` 的最大旋转差，但随后采样立即回落到约 `0.1°`，没有持续来回振荡。这是 `180/-180/180` 与 `0/0/0` 两套等价欧拉角表达之间的切换，不代表模型真的旋转了半圈。
- 攻击或连招进行中，受伤仍会正常结算，但不会用全身受伤动画覆盖已经承诺的攻击动作。
- 非攻击状态下，近距离合法近战攻击者会被立即锁定并触发反击；远程或距离外攻击者允许当前短受伤动作播完后再追击。
- 第一段容易挥空的问题已通过最多 `0.75` 格的安全追踪修正缓解。现有日志确认过一次从约 `4.49` 格起手并在第一段成功命中的案例。

## 模型师后续更新时需要注意

### 1. 连招末帧的欧拉角表达

- 当前代码已经遮蔽了等价欧拉角切换造成的单帧风险，因此现有模型不要求仅为此返工。
- 如果以后重新导出连招，建议把动作末帧显式收回到与待机首帧相同或非常接近的旋转数值，尤其注意 `Main`、`Body`、`Upper_Body2` 与持刀手臂。
- 不要只看画面姿势相同；`180°` 与 `-180°` 虽然视觉等价，但插值器可能选择长路径。末帧数值尽量归一到待机所用的同一组欧拉角表示。

### 2. 命中关键帧

- 当前服务器四段伤害关键帧为连招起手后的第 `23 / 43 / 58 / 77` tick，每段允许前后 1 tick 的判定容差。
- 模型师若修改挥刀节奏，需要同时给出新的四个“刀锋真正穿过目标区域”的关键帧；只改变动画而不更新事件帧会使声音、粒子和伤害与动作错位。
- 前三段横扫声与第四段重击/风爆声都直接绑定这些关键帧，即使挥空也会播放。

### 3. 实体位移与根骨骼位移

- 四段真实推进与第一击前的追踪修正由服务端代码负责，以保证碰撞、台阶、墙体、悬崖和多人同步正确。
- 动画可以表现重心前移，但不要依赖水平根骨骼位移推动游戏实体，也不要在新版动作中额外累计一套不可控的长距离位移。
- 一格高低差由实体步高平滑处理，不需要额外制作跳跃动作。

### 4. 代码接管的面部骨骼

- 眨眼、瞳孔追踪、歪头、玩家对视、苦力怕警觉和受伤表情由代码叠加控制。
- 更新动作时应避免在普通全身动作中持续锁死 `Eyes_Left`、`Eyes_Right` 与 `Eyebrow`。头部可以参与战斗动作，但应保留动作结束后回到中性的能力。

## 仍需实机验收

- 四段伤害扇区是否与刀锋视觉方向一致，尤其是第三段偏转和第四段 `220°` 大范围横扫。
- `4.5` 格起手距离与最多 `0.75` 格追踪修正在大型、细小、快速移动目标上的第一段命中稳定性。
- 四段总推进、一格楼梯升降、墙前停止以及超过一格落差时不冲下悬崖的手感。
- 第一段浮空高度及持续时间是否足够可见，但不会让后续攻击难以命中。
- 第二段正面投射物弹开窗口与动画格挡姿势是否对齐。
- 前三段逐步加重的横扫声是否形成清楚节奏；第四段“大型风弹爆发＋重锤落点＋刀刃重击”的三层声音是否过于拥挤或仍不够有力。
- 第四段小型定向风爆是否出现在刀锋前方合适位置，是否需要调整高度、弧宽或粒子数量。
- 多人环境中的动作、位移、粒子、声音、瞳孔与头部朝向同步。
- 连招冷却为从起手开始的 12 秒；受近战或投射物实际伤害时每次减少 0.5 秒且无上限。需要观察高压战斗中允许连续连招是否达到预期强度。

## 诊断方式

动画诊断默认关闭。需要复查动作边界时，对玩家 32 格内最近的所属关刀甲胄战士使用：

```mcfunction
/echo_warrior animation_debug guandao on
```

复现后检查 `run/logs/latest.log` 中的：

- `[GuandaoAnimationServer]`：动作起止、命中窗口、追踪修正、反击与控制器释放。
- `[GuandaoAnimationBonesClient]`：动作结束前后关键骨骼的帧间变化。

完成采样后关闭，避免产生大量日志：

```mcfunction
/echo_warrior animation_debug guandao off
```
