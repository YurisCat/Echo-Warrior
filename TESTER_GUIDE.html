Echo Warrior · Tester Kit

测试环境获取与更新指南

不需要 Git 基础，也不需要单独安装 Java。第一次从 QQ 离线包开始；以后只获取 GitHub 上较小的代码更新。

Windows 10/11 x64 目标分支：main 离线包日期：2026-08-27 测试世界：CATTEST

第一次只需：解压、检查、启动

QQ 离线包已经带上 PortableGit、Java 25、测试世界和构建依赖。不要在压缩软件预览窗口里直接运行文件。

开始前请让开发者完成

把你的 GitHub 账号加入私有仓库协作者，并确认你已经接受邀请。首次检查不联网，但以后更新需要此权限。

  1. 1

    完整解压 QQ 收到的 ZIP

    建议解压到较短、容易找到的路径，例如 D:\Echo-Warrior-Test。不要只拖出其中几个文件，也不要直接在 ZIP 内双击 BAT。

  2. 2

    双击 首次安装.bat

    它不会安装系统软件，只检查包内 Git、Java、Gradle 缓存和 CATTEST，再执行一次离线编译。看到绿色“首次检查完成”即可。

    若 Windows 安全提示阻止运行，可右键原始 ZIP → 属性 → 勾选“解除锁定”，然后重新解压。

  3. 3

    双击 启动测试.bat

    脚本会使用包内 Java 与离线缓存编译项目，随后启动 Minecraft 并进入 CATTEST。第一次启动通常比以后慢。

  4. 4

    以后不要重新解压整个包

    收到“代码已更新”的通知后，切换上方的“每次强制更新”标签页，按那里操作即可。测试世界和游戏设置会继续保留。

为什么没有普通的 GitHub 克隆步骤？

项目源码本身不大，真正耗时的是 Gradle、Minecraft、Fabric 与模组依赖。离线包已经包含一个可继续更新的 Git 工作目录，因此第一次不必从 GitHub 下载完整项目。

排障：我想确认 PortableGit 和离线编译是否可用

在项目根目录空白处按住 Shift 右键，选择“在终端中打开”，依次执行：

PowerShell · 首次检查的核心命令
.\.toolchains\portable-git\cmd\git.exe --version
.\.toolchains\jdk-25\bin\java.exe -version
$env:GRADLE_USER_HOME = "$PWD\.toolchains\gradle-user-home"
.\gradlew.bat --offline --no-daemon classes
备用：没有离线包时，普通克隆命令是什么？

以下命令只能取得源码；它不会自动提供 Java 25、CATTEST 和离线依赖，因此仍应优先使用完整离线包。

PowerShell · 仅克隆源码
git clone https://github.com/YurisCat/Echo-Warrior.git Echo-Warrior-Test
cd Echo-Warrior-Test

更新时强制以远端代码为准

这套流程适合只负责测试、不需要保留源码修改的电脑。生成的测试世界、配置、截图和日志不会因为强制更新而消失。

日常最短流程

关闭 Minecraft → 双击 强制更新.bat → 等待绿色成功提示 → 双击 启动测试.bat。

强制更新会抛弃源码改动

如果你手动改过 Java、资源、脚本或文档，这些修改会被远端 origin/main 覆盖。需要保留的反馈请发到 QQ、截图或项目目录之外的文档中。

  1. 1

    正常关闭 Minecraft

    不要让旧版本客户端继续运行。更新脚本检测到本项目客户端仍在运行时会停止，并提示先关闭游戏。

  2. 2

    双击 强制更新.bat

    第一次连接私有仓库时可能弹出浏览器。登录被开发者邀请的 GitHub 账号并授权 Git Credential Manager；以后通常不需要重复登录。

  3. 3

    等待代码覆盖和离线构建检查

    看到绿色“更新成功”才表示本轮完成。如果提示缺少新依赖，不要反复重试下载，直接向开发者索取新版离线支持包。

  4. 4

    双击 启动测试.bat

    更新脚本不会自动打开 Minecraft，避免把 Git、构建与游戏启动错误混在一起。

会被覆盖或清理

  • 受 Git 管理文件的本地修改
  • 未被 Git 管理的散落源码文件
  • 已经从远端删除的旧代码

会继续保留

  • run/ 与 CATTEST 世界
  • 游戏配置、截图、日志与崩溃报告
  • 包内 Java、PortableGit 和离线缓存
  • 本指南及三个测试员 BAT 入口
脚本实际执行了哪些 Git 命令？

reset --hard 负责抛弃受管理文件的修改；clean -fd 负责移除非忽略的散落文件。它没有使用危险的 clean -fdx，所以不会删除测试环境。

PowerShell · 强制同步核心命令
.\.toolchains\portable-git\cmd\git.exe fetch --prune origin main
.\.toolchains\portable-git\cmd\git.exe reset --hard origin/main
.\.toolchains\portable-git\cmd\git.exe clean -fd
$env:GRADLE_USER_HOME = "$PWD\.toolchains\gradle-user-home"
.\gradlew.bat --offline --no-daemon classes
提示没有仓库权限或登录失败

确认 GitHub 账号已经接受开发者发送的私有仓库协作者邀请，并确保浏览器登录的是同一个账号。仍失败时，把命令窗口完整截图发给开发者。

提示离线模式缺少依赖

这通常表示项目升级了 Gradle、Minecraft、Fabric API、SmartBrainLib 或 GeckoLib。代码可能已经更新成功，但旧缓存无法构建；请索取新版离线支持包。

为什么测试产生很多文件却不影响 Git 更新？

run/、build/、.gradle/ 和 .toolchains/ 已被项目忽略。Git 默认不把这些运行产物当成源码修改，因此强制更新只需要覆盖真正的项目文件。
